# ShareX-Mod v0.10.3-dev — Range-aware Template Routing

This update feeds v0.10.1 semantic range placeholders back into the multi-family Template Router.

## The ambiguity it addresses

Two page families can share exactly the same Next Page control and have no family-specific buttons. The earlier Router correctly stopped as ambiguous in that situation, but it could not use the fact that Family A's demonstrated capture range was anchored near one article/content structure while Family B was anchored near another.

## Evidence weights

The Router now builds two classes of evidence:

- required reviewed actions such as Next Page: weight 4 and still fail-closed;
- optional semantic actions: weight 2;
- vertical-range start/end semantic placeholders: weight 1 each and never safety-critical.

A missing range anchor reduces confidence but does not invalidate a family. A missing required Next/action invalidates the family even if all range anchors match. This prevents positional evidence from rescuing an unsafe navigation decision.

## DOM probing

When a locator has no id/test-id, the probe can now query its recorded semantic tag (for example `article`, `section`, `p`, `figure`) instead of limiting candidate search to interactive controls. Historical X/Y geometry remains a very weak tie-breaker only.

## Regression tests

A pure evidence-scoring test verifies both sides of the rule:

1. matching start/end range placeholders provide useful separation between two families that share the same required Next evidence;
2. range evidence cannot make a family valid when the required Next/action locator is unresolved.

The runtime still requires the configured minimum family score and uniqueness gap. If the best family is not uniquely supported, automation stops with `ambiguous-family` and the resume journal is marked for review.
