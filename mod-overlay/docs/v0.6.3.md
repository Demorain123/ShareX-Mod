# ShareX-Mod v0.6.3-dev — resilient page transitions and complete Recipe appendices

v0.6.3 strengthens two failure modes that matter for unattended complex captures.

## Same-URL / SPA pagination

A recorded `NextPage` action no longer requires the browser URL to change.

Before the action, the runner samples the current main-content state. The fingerprint is built from visible semantic content inside `main`, `[role=main]`, `#content`, common content containers, or the document body as a fallback. Navigation chrome and the clicked button itself are therefore less likely to dominate the signal.

After the semantic locator is re-resolved and clicked, the transition succeeds when either:

- the URL changes; or
- the main-content semantic fingerprint changes and remains changed across multiple probes.

Structural changes such as document-height or semantic-element-count changes strengthen the same-URL decision. A same-size virtualized page is still accepted when the new main-content fingerprint remains stable for three observations.

If none of these conditions is verified before timeout, unattended capture stops instead of guessing that the page changed.

## Recipe appendix composition

Automated Recipe captures now use a dedicated v0.6.2+ entry that composes the capture in this order:

1. fixed-range Recipe runner or dynamic-feed runner;
2. validated horizontal sweep panorama/tail pages;
3. browser original-image export;
4. native 1:1 image tail pages;
5. final full PNG and preview.

Horizontal panorama joins must pass pixel overlap validation. Ambiguous joins remain as independent source panels.

Original browser images are never scaled down merely to fit a tail page. Oversized assets are split into native-resolution x/y slices.

## Original-image retention

`chromeImageAppendixOriginalRetention` supports:

- `keep`
- `delete`
- `ask`

`ask` is the default. Until a visible retention prompt is connected to the ShareX UI, unattended/background capture falls back safely to keeping the originals and writes `original-retention-pending.json`. Deletion is only attempted after the image has been successfully embedded in the final capture.

## Why this is not mouse-macro replay

The runner still treats recorded positions as weak evidence. It re-resolves actions by id/test-id/role/aria/name/href/text, checks uniqueness, verifies the resulting page transition, and then continues. Coordinate replay is not the authority.
