# ShareX-Mod v0.6.2-dev — partial capture, dynamic feeds and horizontal appendices

v0.6.2 closes three important gaps in Capture Recipe behavior.

## Partial Start/Stop capture with no scrolling

A demonstration can start and stop in the middle of a page without moving the wheel at all. The compiler now seeds every recorded page with its initial visible viewport as a minimum `CaptureVerticalRange`.

This preserves the ShareX behavior where Start/Stop defines a partial content boundary rather than implicitly requesting a full page.

If the user scrolls down, back up to inspect slow-loading content, and then continues, the recipe expands the content coverage range. It does not replay the literal wheel sequence.

## Dynamic / infinite feeds

A single-page demonstration is inferred as a dynamic feed only when:

- the same page remains active;
- no semantic Next Page action was recorded;
- multiple document scroll observations exist;
- document height grows meaningfully during the demonstration;
- the final observation is near the then-current bottom.

The resulting recipe uses `dynamic-feed` as its stop-boundary kind.

The background runner captures known content, moves to the live bottom only to trigger the site's own lazy/infinite loading, waits for region stability, and re-reads document height. New height extends the capture boundary. Consecutive passes with no growth terminate the run.

Manual Stop remains authoritative. Bounded step, duration, unchanged-pass and maximum-CSS-height limits prevent an unattended feed from running forever.

## Horizontal content

A recorded nested horizontal scroller is still captured as overlapping visual panels. v0.6.2 now validates adjacent panels with real pixel overlap matching before it builds a panorama.

The matcher searches a bounded overlap range and compares luminance plus horizontal/vertical edge gradients. It requires both:

- a sufficiently low best score;
- a sufficient uniqueness gap from the second-best overlap.

If any join is ambiguous, the source panels are kept independently and the software does not invent a panorama.

A verified panorama is preserved at native 1:1 pixels and sliced into normal-width tail pages. These pages are appended after the vertical long screenshot, so horizontal content does not make the main capture extremely wide.

Evidence is written to `horizontal-appendix/horizontal-appendix.json`.

## Safety defaults

- Recipe recording remains disabled by default.
- Recipe automation remains disabled by default.
- local repair auto-apply remains disabled while alignment thresholds are validated.
- dynamic-feed automation only runs for a recipe explicitly classified as `dynamic-feed`.
- horizontal stitching fails closed when overlap evidence is ambiguous.
