# ShareX-Mod v0.6.0-dev — Capture Recipe foundation

The old working name "imitate screenshot" is intentionally replaced by **Capture Recipe**. The goal is not to replay raw mouse coordinates or wheel counts. The recorder learns the intended capture coverage, semantic actions, boundaries and page state.

## Recorder

When both Chrome Enhanced and `captureRecipeRecordingEnabled` are enabled, ShareX-Mod injects a lightweight recorder into the selected Chromium page. It is also registered for newly created documents so navigation can continue recording.

The C# side polls and drains a bounded in-page event queue. This avoids changing the existing CDP client's request/response loop while still retaining events before page navigation discards the old JavaScript context.

Recorded evidence includes:

- page URL/title and document/viewport dimensions;
- document scroll positions;
- nested horizontal/vertical scroller positions;
- trusted user clicks;
- semantic target attributes (`id`, `data-testid`, role, aria-label, name, text, href, rel, type);
- absolute target geometry.

## Normalization

Raw scrolling is not replayed literally.

Repeated document scroll events on the same page are merged into `CaptureVerticalRange` coverage. A user can scroll down, back up to inspect slow-loading content, and then continue: the recipe describes the content range that must be captured and stabilized rather than the exact wheel sequence.

Nested horizontal scrolling becomes `HorizontalSweep` intent. Trusted element activations become `ExpandOrActivate` unless they look like a pagination transition, in which case they become `NextPage`.

## Boundaries

Recipe start records the demonstration's document position. The stop boundary remains `manual-or-configured-condition`, preserving ShareX's Start/Stop model. Existing optional max-step, max-duration and no-new-content limits are copied into the recipe as safety conditions rather than forcing full-page capture.

## Locator philosophy

A recorded locator stores semantics first and geometry last. Future replay must re-resolve the element in the current page and verify the resulting page state before continuing. Backend/session-specific identities are evidence, not permanent replay coordinates.

## Current safety defaults

- `captureRecipeRecordingEnabled = false`
- `captureRecipeAutomationEnabled = false`
- normal ShareX capture is unchanged
- recipe recording requires Chrome Enhanced
- automatic page actions are not enabled by this version

The next layer adds locator re-resolution, replay preflight and deterministic capture phases before any unattended clicking is enabled.
