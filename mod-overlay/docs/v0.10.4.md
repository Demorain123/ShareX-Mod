# ShareX-Mod v0.10.4-dev — Safer Pagination Intent

This update removes the broad `text.Contains("next")` pagination heuristic from Capture Recipe compilation.

## Why

A demonstrated click whose label contains the word `next` is not necessarily page navigation. Examples such as `Next.js`, `Next comment`, `Next image` or `What's next?` can be legitimate controls/content and must not become an unattended `NextPage` step.

## High-confidence evidence

The classifier now accepts pagination when it has one of these stronger signals:

- a `rel` token exactly equal to `next`;
- an interactive control with an exact normalized label such as `Next`, `Next page`, `Go to next page`, `下一页`, `下一頁`, `次へ`, `다음 페이지`, and a small multilingual set;
- an exact normalized identifier such as `pagination-next`, `pager-next`, `page-next`, `next-page`, `btn-next`.

Punctuation and arrow glyphs around an otherwise exact label are normalized away, so `Next…` and `下一页 ›` remain valid.

## What no longer counts

Arbitrary substring matches do not count. `Next.js`, `Next comment`, `Next image`, `What's next?`, and non-interactive text containing only `Next` are regression-tested as negatives.

This remains intentionally conservative. If a site uses only a bare arrow with no semantic `rel`, accessible label or stable pagination identifier, Capture Recipe will treat the click as an ordinary semantic action rather than guessing that it changes page. The user can still demonstrate/review a better-supported pagination control.

The HTML Living Standard defines `rel=next` as the next logical document in a sequence, which is why it is treated as the strongest portable signal.
