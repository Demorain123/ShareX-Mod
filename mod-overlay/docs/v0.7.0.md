# ShareX-Mod v0.7.0-dev — simple Capture Mode UI

v0.7 starts converting the long-screenshot work from an advanced configuration project into a workflow normal ShareX users can understand.

## Three modes

The Scrolling Capture window gains one compact mode selector:

- **Normal scrolling capture** — preserves the original ShareX Start/Stop workflow and disables Recipe recording/replay for this capture.
- **Record Capture Recipe** — enables Chrome Enhanced + semantic Recipe recording while the user demonstrates the desired content/actions.
- **Run latest Capture Recipe** — enables background Recipe execution and automatically resolves the latest recorded `capture-recipe.json` when no explicit path is configured.

The mode is persisted in `ShareX-Mod/capture-mode.json` rather than requiring the user to edit the large advanced settings file.

## Start/Stop remains primary

This UI is deliberately not a replacement for ShareX Start/Stop. Partial-page capture remains the default mental model: choose the content area, start where desired, stop where desired.

Capture Recipe is an extra workflow for pages whose content requires semantic actions, pagination, horizontal sweeps or dynamic-feed continuation.

## Current-capture settings reload

The mode can be changed while the Scrolling Capture window is open. Immediately before the actual capture begins, the overlay settings are reloaded so the selected mode applies to the current capture instead of only the next application launch.

## Fail-open behavior

The mode panel is attached programmatically around the existing Avalonia window content. Attachment exceptions are swallowed: an incompatible UI change must never prevent the original ShareX scrolling-capture window from opening.

The first v0.7 UI intentionally exposes only the mode and the latest Recipe identity. Matcher, CDP, quality, repair and segmentation parameters remain advanced settings rather than becoming another overwhelming toolbox.
