# ShareX-Mod v0.10.2-dev — Post-capture Integrity Manifest

v0.10.2-dev adds a byte-integrity layer after the semantic/position quality stack. It is intentionally post-capture so it cannot slow the live scrolling/capture loop.

## Two different kinds of validation

A SHA-256 match proves that a saved file still contains the same bytes that were hashed. It does **not** prove that the web page was completely captured. ShareX-Mod therefore keeps the two responsibilities separate:

- Semantic Placeholder, stability probes, Page Guard, Rolling Guard and Position Ledger check whether the intended page regions were captured and whether output coverage is coherent.
- The Integrity Manifest checks whether the saved output/metadata bytes later remain unchanged and present.

## Output

After Position Ledger generation, the current Recipe entry writes:

- `recipe-quality/capture-integrity.json`
- `recipe-quality/capture-integrity.sha256`

The JSON contains a SHA-256 for each selected active output file, file length, category, the primary `capture-full.png` digest when present, and a deterministic bundle digest over the sorted file list.

## Performance policy

Hashing begins only after scrolling, repair, appendices and quality-ledger work have completed. Files are read with asynchronous sequential FileStreams and `SHA256.HashDataAsync`.

Core PNG output and JSON/TXT metadata are included by default. Native original assets under `image-appendix/` are not hashed a second time by default because the Page Loop and Dynamic Feed collectors already calculate SHA-256 for those files while deduplicating them. Set `captureIntegrityIncludeNativeAssets=true` when a second full-bundle pass is desired.

Transient export folders and stale/replaced forensic parts are excluded from the active-output bundle.

## Verification API

`ShareXModCaptureIntegrityManifest.VerifyAsync` re-hashes the files listed by the manifest and reports missing or mismatched files. The Fast Semantic Gate includes a regression test that first verifies a newly written manifest and then deliberately mutates a saved file and requires verification to fail.

The bundle digest is intended for accidental corruption/change detection and for comparison with a separately stored value. It is not a digital signature and does not provide authenticity against an attacker who can modify both the files and the manifest.
