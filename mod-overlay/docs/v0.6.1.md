# ShareX-Mod v0.6.1-dev — background Capture Recipe runner

v0.6.1 turns the semantic recipe from a recording artifact into an optional background capture path.

## Execution path

When all of the following are true:

- Chrome Enhanced is enabled;
- Capture Recipe automation is enabled;
- `captureRecipeReplayPath` points to a recipe file;

ShareX-Mod attempts the Recipe runner before generic Chrome background full-page capture.

This preserves the recipe's partial ranges, semantic actions, pagination and horizontal sweeps instead of flattening everything into a full-page command.

## Vertical ranges

`CaptureVerticalRange` is captured directly with CDP in bounded tiles. Each tile uses region stability checks before `Page.captureScreenshot`. Captured tiles are persisted as recipe-run parts and combined into `capture-full.png` when their widths are compatible.

## Semantic actions

`ExpandOrActivate` and `NextPage` do not reuse recorded screen coordinates. The current DOM is searched again and candidate elements are scored using stable semantics first:

1. id;
2. data-testid/test-id/test;
3. role + aria-label;
4. name/href;
5. rendered text;
6. recorded geometry only as weak tie-breaking evidence.

An action requires both a minimum match score and a uniqueness gap from the runner-up candidate.

`NextPage` additionally requires observable navigation. If the click cannot be resolved uniquely or navigation is not observed before the configured timeout, unattended execution stops and records the failure.

## Horizontal sweep

A recorded horizontal-scroll container is re-resolved semantically. The runner advances its `scrollLeft` in overlapping viewport-sized steps and captures each visible panel to a dedicated `horizontal_step_XXXX` directory. These remain appendix material rather than forcing the main long screenshot to become extremely wide.

## Fail-safe defaults

`captureRecipeAutomationEnabled` remains false by default. Recording and replay are separate capabilities. A user can therefore build and inspect a recipe without allowing unattended page actions.

The runner writes `recipe-run.json` with every page checkpoint, action decision, navigation result and captured vertical part.
