# ShareX-Mod v0.5.2-dev

Focus: make long-scroll capture quality guarding bidirectional and session-aware.

## Added in the v0.5 line

- Semantic Capture Map using browser layout/DOM evidence.
- Start/end semantic snapshots for moved/resized-content detection.
- Layout-shift evidence while capture is active.
- Win32 screen-pixel to browser CSS/DIP calibration evidence.
- Local repair candidates generated only for suspect logical ranges.
- Bounded stability checks around each repair range.
- Pixel alignment gate before any destructive replacement.
- Support for both normal in-memory results and smart-segmented ultra-long captures.
- Final `quality-summary.json` and `quality-summary.txt`.

## Bidirectional quality loop

Pixel capture can create suspect ranges through the Capture Map / Quality Guard. Browser evidence can also add ranges when the page changes after an earlier screen frame was already accepted.

Examples include:

- images or embeds loading late;
- web fonts changing text layout;
- ads/comments inserting above already-captured content;
- semantic anchors moving or changing height;
- recorded layout shifts affecting an already-captured logical range.

The merged repair plan is then handled by the same browser re-capture and alignment path.

## Fail-safe behavior

`chromeRepairAutoApplyEnabled` currently defaults to `false` while the alignment thresholds are validated on real sites. The system still performs stability analysis, captures repair candidates, runs alignment verification, and writes a complete audit. Turning auto-apply on later does not require redesigning the pipeline.

A failed stability or alignment gate never overwrites the original screenshot.

## Final status

The summary reports one of:

- `clean`
- `repaired`
- `partially-repaired`
- `unresolved`

This lets the user distinguish "file saved successfully" from "the long screenshot has evidence that all captured logical ranges are trustworthy".
