# ShareX-Mod v0.7.3-dev — extensionless dedicated Capture Browser

v0.7.3 adds a practical extensionless Chrome/Edge path that does not attach remote debugging to the browser's default profile.

## Dedicated persistent profile

The Capture Mode UI can launch a separate persistent Capture Browser profile with:

- a non-default `--user-data-dir` owned by ShareX-Mod;
- `--remote-debugging-port=0` so Chromium allocates a localhost port;
- the actual port read from `DevToolsActivePort`;
- no browser extension.

The profile persists across runs. A user can sign in to sites inside this Capture Browser once and reuse that authenticated profile later.

This is intentionally separate from the user's default Chrome profile. It is an interim path while permission-gated attachment to an already-running default browser session remains a provider that must be implemented only through an officially supported connection mechanism.

## Connection Broker

The Chrome connection layer is provider-based. It can resolve, in order:

1. an already-running dedicated Capture Browser profile;
2. an explicitly configured endpoint;
3. `SHAREX_MOD_CDP_ENDPOINT`;
4. a small loopback-only local discovery range.

Non-loopback DevTools endpoints are rejected by default.

The simple Capture Mode UI reports which provider is ready. Record/Run features therefore no longer need to assume that port 9222 is the only way to connect.

## UI

Record/Run modes expose **Open Capture Browser**. Starting it never disables Normal ShareX Start/Stop capture. The UI explicitly describes it as a separate persistent profile so users are not led to believe their ordinary Chrome profile is being controlled.
