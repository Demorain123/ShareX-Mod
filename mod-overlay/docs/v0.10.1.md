# ShareX-Mod v0.10.1-dev — Semantic Range Placeholders

This update connects the existing range-anchor resolver to Capture Recipe recording so vertical capture ranges can follow document layout shifts instead of relying only on historical absolute Y coordinates.

## Semantic boundary sampling

During Recipe recording, ShareX-Mod samples only a few points near the visible top and bottom edges of the browser viewport. It walks a short ancestor chain and prefers meaningful document elements such as articles, headings, paragraphs, list items, figures, images and elements with stable id/test-id/role/ARIA evidence.

The recorder deliberately does **not** scan the full DOM on every scroll. Fixed and sticky elements are excluded from these range-boundary samples so a persistent toolbar is not accidentally used as a content placeholder.

## Compiled range placeholders

A vertical range can now contain:

- a semantic start locator;
- a start offset from that locator to the demonstrated range boundary;
- a semantic end locator encoded in Recipe evidence;
- an end offset from that locator to the demonstrated range boundary.

At replay time the existing Range Anchor Resolver re-resolves those semantic elements on the current DOM. If content inserted above the range moves both anchors, the capture range moves with them. If only the start anchor can be resolved uniquely, the whole recorded range is translated by the same delta. If semantic resolution is ambiguous, the old recorded coordinates remain the safe fallback and Page Guard can still detect/repair stale output.

## Why this matters

This is the direct implementation layer for the earlier “placeholder / actual page position” idea: comments, posts, image blocks and similar content regions are no longer represented only as pixels from the top of the page. The screenshot still preserves exact output positions, but the *intent* of a range can be reconstructed from nearby semantic content when lazy loading or expanded content changes the document length.

## Regression gate

The Fast Semantic Gate now runs both the existing five planner tests and a range-anchor compilation test. The new test verifies that a recorded top/bottom semantic sample becomes start/end anchor evidence with the correct offsets before the full Release/Portable build is allowed to continue.
