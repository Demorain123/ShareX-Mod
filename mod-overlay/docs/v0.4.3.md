# ShareX-Mod v0.4.3-dev

Focus: make Start/Stop a first-class capture boundary and convert v0.4.2 quality evidence into local repair plans.

## Capture Boundary

The existing ShareX Start/Stop workflow remains the default. All automatic numeric limits are disabled when set to `0`.

Optional boundaries:

- `captureBoundaryMaxSteps`: stop after N accepted appended capture steps;
- `captureBoundaryMaxDurationSeconds`: stop after the configured elapsed time;
- `captureBoundaryMaxLogicalHeight`: stop after the logical long-capture height reaches the limit;
- `captureBoundaryMaxUnchangedPasses`: stop an infinite feed after N consecutive unchanged captures.

This creates a foundation for later UI presets such as:

- Manual Start / Manual Stop;
- Start here / capture 100 steps;
- Start here / capture 10 minutes;
- Start here / capture 50,000 logical pixels;
- Infinite feed / stop after N no-new-content passes.

The default configuration has every automatic limit set to zero, so the current hotkey behavior is unchanged.

## Repair Plan

v0.4.2 writes `capture-map.json` and marks suspect logical ranges. v0.4.3 reads that report after capture and writes `repair-plan.json` next to it.

Each suspect range is:

1. expanded by a configurable safety margin;
2. clamped to the captured logical height;
3. merged with nearby suspect ranges;
4. preserved with the original failure reasons.

The plan is deliberately passive in v0.4.3: it does not re-scroll or re-capture anything yet.

The planned follow-up browser repairer can map these logical ranges to absolute page coordinates and use CDP `Page.captureScreenshot` clips to replace only damaged content instead of repeating the full long screenshot.

## Chrome background settings

The shipped `ShareX.Mod.v04.json` now exposes the already-existing background capture StartY/EndY, tile size, natural-cut, image-wait, stable-bottom, max-parts and max-CSS-height settings so the partial/background capture path is discoverable without manually guessing property names.
