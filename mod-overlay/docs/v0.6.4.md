# ShareX-Mod v0.6.4-dev — output position ledger and browser overlay groundwork

v0.6.4 turns Capture Recipe output into an auditable document mosaic instead of a collection of screenshots.

## Final output position ledger

Every final output range is mapped back to its origin when evidence is available:

- final output start/end Y;
- source part file;
- vertical content vs horizontal appendix vs native image appendix;
- Recipe step and PageKey;
- original document CSS start/end Y.

The ledger is written to `recipe-quality/recipe-position-ledger.json`.

This is the basis for local repair and later resume/retry behavior: a bad final region can be traced to the page and capture intent that produced it.

## Coverage audit

Each requested `CaptureVerticalRange` is checked against the parts actually written to disk. The audit detects:

- a requested range with no output part;
- missing top/bottom edges;
- gaps between adjacent output parts;
- final PNG dimension mismatch against the ledger.

Dynamic-feed captures are checked by document-Y overlap rather than by fixed Recipe step IDs because the feed boundary can grow after recording.

The user-oriented result is written as:

- `recipe-quality-summary.json`
- `recipe-quality-summary.txt`

Possible states include `complete`, `bounded-stop`, `coverage-gap`, `output-dimension-mismatch`, and `failed`.

## Fixed/sticky overlay groundwork

`ShareXModChromeOverlayDeduplicator` records bounded visible `position: fixed` / `position: sticky` elements and can temporarily hide them during later tiles without permanently mutating the page.

This is intended to eliminate repeated browser overlays such as a floating Back/page indicator from a multi-tile Recipe capture. The helper is deliberately separate from the existing pixel-mode static-overlay cleaner. Its actual per-tile integration is the next small version so the new hot-path behavior can be validated independently.

## Safety

Recipe recording and Recipe automation remain disabled by default. Browser local-repair destructive auto-apply also remains disabled while real-world alignment thresholds are being validated.
