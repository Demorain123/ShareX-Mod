# ShareX-Mod v0.4.2-dev

Focus: capture-position bookkeeping, lazy-load guarding and local repair foundations.

## 1. Capture Map / Position Ledger

A long capture is no longer treated as anonymous screenshot frames. Each accepted frame receives a logical document range derived from independent scroll-delta evidence.

For each frame the ledger records:

- logical top / bottom;
- estimated scroll delta;
- actual stitched growth;
- anchor score and agreement count;
- adaptive-settle outcome;
- fallback-combine use;
- repaired fixed-overlay tile count;
- quality statistics for the newly exposed strip.

The result is written as `ShareX-Mod/CaptureQualitySessions/.../capture-map.json`.

## 2. Quality Guard

The hot capture path stays lightweight. It reuses low-resolution fingerprints, anchor deltas and overlap evidence; OCR/AI is not run while scrolling.

Ranges become `suspect` when evidence indicates:

- settle timeout;
- blank-like newly exposed content;
- fallback-only join;
- weak anchor evidence;
- implausible growth compared with independent scroll movement.

The report merges adjacent suspect intervals so a later browser-aware repairer can recapture only those logical Y ranges.

## 3. Slow/lazy content

v0.4.2 compares the lower newly exposed area with the pre-scroll viewport. Normal pages retain the fast settle path. A suspicious new blank/flat area receives a short extra watch; if it remains unresolved at the safety timeout it is captured but marked suspect rather than silently trusted.

## 4. Fixed/sticky overlay suppression

v0.4.1 stopped fixed side UI from dominating matching, but a fixed control could still be copied repeatedly into the output strip.

v0.4.2 adds a conservative temporal repair pass for edge chrome. If a textured tile:

1. stays essentially identical at the same screen coordinate while the page moves;
2. differs from the content one scroll-delta lower in the previous frame; and
3. that previous location contains real detail,

then the compositor uses the prior frame's pixel from the same logical document coordinate instead of writing the fixed overlay again.

The first release limits this to screen-edge chrome to reduce false positives. A future document-mosaic compositor can generalize this using multi-frame validity masks.

## 5. High-resolution image appendix

Oversized appendix images no longer have to be shrunk to fit one tail page. The v0.4.2 appendix writer preserves native pixels and emits multiple bounded tail slices when necessary.

## 6. v0.5 browser Capture Map

When browser-aware transport is available, logical ranges can be upgraded to semantic anchors:

- DOM/layout node bounds;
- text/resource fingerprints;
- absolute document coordinates;
- layout-shift invalidation;
- resource-loading completion.

That allows exact local recapture of a damaged range instead of repeating the complete long screenshot.
