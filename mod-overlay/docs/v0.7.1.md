# ShareX-Mod v0.7.1-dev — readiness feedback and image-retention decisions

v0.7.1 makes the simple Capture Mode layer actionable rather than merely decorative.

## Readiness

Record/Run Recipe modes perform a short, bounded readiness probe. The UI distinguishes:

- ready;
- no Recipe recorded;
- Chrome Enhanced endpoint unavailable;
- Chrome endpoint reachable but no page target;
- connection timeout.

A failed Recipe readiness check does not disable Normal ShareX capture.

## Image appendix Ask flow

Native browser images embedded into the final long screenshot can request `keep`, `delete`, or `ask` retention.

`ask` remains the default. A pending request is surfaced in the Scrolling Capture mode area with:

- **Keep originals**
- **Delete embedded originals**

Deletion is path-restricted. The resolver only accepts files inside approved ShareX-Mod capture storage and only deletes filenames explicitly listed by the pending retention record. Anything outside those roots is refused.

The decision is recorded in a resolved-retention JSON file for audit.

## Fail-open UX

The mode/readiness/retention panel is an additive layer. If it cannot attach or a readiness probe fails, the original Scrolling Capture window remains usable.
